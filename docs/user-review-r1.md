### 1.【P0·3角色】注册资料静默丢失（gender/city 被后端丢弃）

- 根因单点：`server/src/routes/auth.js` 手机号注册分支 INSERT 硬编码 `gender='secret', city=''`，忽略请求体字段；而前端注册表单（login.js）收集并提交了这两个字段。
- 连锁伤害：女生局对全体手机号注册女性关闭（P0）→ 兴趣/同城推荐输入缺失 → 发布表单不预填 → 老搭子推送的"同城"判定失真（新注册用户永远匹配不上）。
- 修法：register 写入 body 女生/男生/保密与城市（1 行 SQL 改动）+ 存量用户在编辑资料引导补全。

### 2.【P1·2角色】通知/角标体系断链
- 涉及：[小林]#2（角标亮在"我的"但"我的"页无通知入口，铃铛藏在广场顶部）+ [搭子王]#2（通知不可点击跳转、进页即全读）
- 用户后果：最关键的两条转化通知——"申请已通过"（小林的会话入口）与"收到新申请"（搭子王的审批入口）——都不能一步到达动作现场。
- 修法：notif-item 按 data.post_id 深链；角标可点；已读改单条。

### 3.【P1·2角色】等待-审批闭环不完整
- 涉及：[小林]#2/#3（申请后无进度反馈、"我的搭局"默认落错 tab）+ [搭子王]#3（满员后剩余申请悬置无通知）+ [搭子王]#6（空留言转嫁审批成本）
- 用户后果：申请端"焦虑等待"，审批端"信息不足+悬置申请"，两端的信用飞轮（互评/搭力）启动都被拖慢。
- 修法：申请状态卡（我的搭局默认 tab 跟随身份）+ 满员自动婉拒 + 申请留言默认预选模板。

### 其他跨角色问题（P2 级）
- 【2角色】表单文字输入负担/缺选择器：[老王]#3（时间手打）+ [Amy]#6（SOS 位置手填）+ [小林]#5（申请留言）——高频输入位缺结构化组件。
- 【2角色】SPA 页面生命周期粗糙：[Amy]#4（弹层跨路由残留）+ [搭子王]#4（审批整页重绘）+ [小林]#1（引导 sheet 挂错页面）——本质都是"整页 innerHTML 重绘"模式的副作用。

## 一句话结论

**最扎心 1 条**：Amy 是个注册时明确选了"女生"的女性用户，申请女生局被系统拒绝——"该搭局仅限女生参加"（根因：注册 API 把她的性别丢了）。安全敏感性最强的用户，在安全/性别功能上被平台背叛一次。

**各角色刺数**：小林 6（P1×3）/ Amy 9（P0×1, P1×2）/ 老王 6（P0×1, P1×1）/ 搭子王 7（P1×3），共 28 条。

**共性 Top3**：① 注册 gender/city 静默丢失（P0，3 角色复现，1 行修复）② 通知/角标断链（通知不可点+入口错位）③ 等待-审批闭环不完整（焦虑等待+申请悬置+空留言）。
