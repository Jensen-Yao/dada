# 搭搭 App 调研报告与产品设计依据

## 一、博主戚越QYUE的搭子App复盘（用户指定参考）

来源：B站视频《我花了近百万，做了一款专门找搭子的APP，结果。。。。。。》
（BV1HH4y1c7E4，2024-07-18发布，播放10.8万，时长36分钟，评论836条）

### 已确认的事实
- 戚越投入**近百万**资金做搭子App，最终收入仅 **72 元**，视频定位为失败复盘。
- 开发走外包团队烧钱；产品经理"完全就是个执行"；**没做需求分析**是评论区公认的最大败因。

### 评论区高赞洞察（>800条评论中最核心的三条）

1. **"人性"问题（297赞）**：任何社交搭子App大概率失败——Momo、Soul都被玩成"炮神聚集地和骚扰软件"。用户目的性强、素质参差，社交软件有天然的刻板印象 decay 路径。
2. **微信黑洞问题（43赞回复）**："以圈子为基础的社交方式，不管任何渠道最后都会转化成微信好友和微信群"——搭子一旦约上，关系就流失到站外。
3. **验证顺序问题（293赞）**：先拉微信群/活动页验证需求2-3个月，别直接开发App；先有流量和受众再开发。

### 搭搭的针对性应对（本产品如何回答这三个问题）

| QYUE遇到的坑 | 搭搭的应对 |
|---|---|
| 微信黑洞：约上就流失站外 | ① 聊天内容自动过滤"加微信/VX"等导流词；② **搭后互评+搭力值**闭环——评价必须回App完成，搭力值是"社交货币"，离开App就失效；③ 历史搭子沉淀在个人主页（搭子履历） |
| 人性 decay：约炮化/骚扰 | ① 私信门槛——必须先申请过对方的搭局才能私聊；② 涉黄暗语词库（"费用全包"等）自动拦截；③ 女性保护：仅限女生局、SOS紧急求助、一键拉黑；④ 搭力值<300禁发布；⑤ 3次违规自动封号；⑥ 运营后台举报队列 |
| 需求验证成本高 | **H5网页版零安装**：手机浏览器直接打开即用，二维码一扫就能验证需求，无需上架应用商店；种子数据内置真实感搭局，冷启动演示成本低 |
| 外包烧钱/产品经理只会执行 | 纯 Node.js 内置 SQLite 零原生依赖，单机可跑，部署成本≈0 |

## 二、市场案例要点

- **市场规模**：2025年搭子经济广义规模突破1500亿元、用户超3.2亿；Soul报告称72.6%受访青年有搭子。
- **主要玩家**：Soul（兴趣图谱+群聊派对）、咕哇找搭子（小程序，实名+人脸）、晖伴（四重认证）、DayOfUs（精致饭局）、可搭吖（女性专属）、嗒伴（游戏开黑）、豆瓣小组（发帖+评论区筛选+拉微信群，"搭子旅行"小组假期前周增2000人）。
- **豆瓣模式是最被验证的原型**：发帖→评论区筛选→建群，但体验原始且最终流失到微信。

## 三、赛道四大顽疾与搭搭的方案

1. **诈骗（代订酒店/门票诱导转账、杀猪盘变体）** → 转账/保证金/代订词库拦截 + 聊天首条消息安全提示 + 安全中心反诈教育。
2. **涉黄暗语（"费用全包""仅限女生"成黑话）** → 暗语词库发帖即拦 + 举报复审。
3. **女性安全** → SOS紧急求助直达管理员 + 仅限女生局 + 拉黑即时生效。
4. **约到即流失（留存低）** → 搭后互评是核心抓手：完成搭局双方互评换搭力值，搭力值高的用户在广场获得信任曝光，形成"回App评价→攒信用→更容易约到靠谱搭子"的循环。

## 四、功能模块清单（均已实现）

1. 搭局发布/浏览：14种场景分类+时间地点人数+AA方式+性别要求
2. 标签体系：兴趣标签+MBTI+认证标识+搭子履历
3. 匹配推荐：同城/分类筛选、热门排序、"为你推荐"（基于历史参加分类+标签重合）
4. 组局与报名：申请→组局者审批→满员自动转full→完成标记
5. 站内聊天：WebSocket实时+私信门槛+敏感词过滤+首条安全提示
6. 信用体系：搭力值（认证+30/+50，完成搭局+20，好评+10，差评-15，举报-20，<300禁发布）
7. 搭后互评：1-5星+标签词（守时/靠谱/友善/有趣/聊得来/再次约）+评语
8. 安全中心：反诈tips+社区公约+SOS
9. 女性保护：仅限女生局（发帖可选+申请时强制校验性别）
10. 运营后台：数据看板+举报队列（警告/封禁/下架/驳回）+用户管理
