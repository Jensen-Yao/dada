# 小红书产品机制反哺搭搭

> 视角：内容社区工程（双列 feed / 话题 / 搜索）｜基线：v2.9 H 章匹配算法 + 瀑布流已上线｜2026-10-12

## 一、内容分发精髓 → 搭搭的映射

1. **话题标签体系**：搭搭的 14 个分类 chips（`square.js` cat-bar）是运营指定的 taxonomy，回答"这是什么局"；小红书话题（#周末去哪儿）是 UGC 自生长的 folksonomy，回答"谁会搜到它"。分类永远只有 14 个，话题是无限的长尾流量入口，两者是互补而非替代关系。
2. **搜索即服务**：小红书约一半流量来自搜索，搜"五道口 火锅"直达带 POI 的笔记列表。搭搭现状（`posts.js` L118）keyword 只对 title/content 做单关键词 LIKE，无搜索落地页、无历史/热搜引导。找搭子需求天然带"地点+品类"双意图，搜索比刷 feed 更接近成交（申请加入），是被低估的入口。
3. **内容质量信号（收藏>点赞）**：小红书 CES 打分中收藏权重远高于点赞——点赞是即时情绪，收藏是"我之后要用"。映射到搭搭：点赞（heart）弱信号，申请/通过是强信号，中间缺一个"想吃这家/想去这但时间不合"的中强度信号（收藏）。若热度公式以浏览/点赞为主，会系统性推"标题党局"而非"能成局的帖"。

## 二、详情页留存机制

1. **相关推荐**：小红书详情底部是"看了这篇还在看"的无限内循环，用户不出详情页域。搭搭详情在评论区后到底，满员帖的出口仅是"跳回广场首屏"（`post.js` joinBtnText 的 H7 分支）——流量漏斗在详情页末端断掉。应补"看了这场剧本杀的人还在约"：同分类同城 open 帖再分发，满员/已完成帖的存量流量二次利用。
2. **评论区盖楼**：小红书评论是内容的一半（作者答疑、路人晒经历）。搭搭评论区已有（`post.js` loadComments），但无组局者身份标识、无楼层回复，盖楼文化起不来。最小改法：组局者昵称旁加"组局者" pill、回复带 @前缀，让问答能被后来的申请者当"公开 QA"读。
3. **发布模板降低 UGC 门槛**：小红书发布页有话题推荐与模板引导。搭搭发布 14 字段表单对首帖用户偏重；按分类给骨架模板（剧本杀=本名/缺几人/哭点警告，饭搭=菜系/AA/忌口），发布质量提升直接反哺搜索命中与 H 章分类偏好维度（H.0 的"分类偏好"子分依赖历史分布的质量）。

## 三、可落地功能建议（按 ROI 排序）

### 1. 详情页底部「相关搭局」推荐（成本 S，约 1 天）
- **实现**：`post.js` 在 loadComments 后追加 `loadRelated()`：请求现有 `GET /posts?category=X&city=Y&sort=hot&size=10`（前端 filter 掉自身与满员帖，取 6 条），渲染双列 `.wf` + `UI.pinCard`；标题"相关搭局"，样式进 `web/public/css/extensions.css`。零后端改动；后续要"同分类优先同城"加权再升级 `GET /posts/:id/related`。
- **价值**：详情→详情的内循环（小红书核心留存形态）；满员/已完成帖流量不再漏走。**成本**：S，纯叠加区块无回归风险。

### 2. 话题 tag 系统：帖子 #标签 可点聚合（成本 M，2-3 天）
- **实现**：BE `posts.js` postView 增加 `tags`（发布时解析 title/content 的 `#xxx`，`db.js` 幂等 ALTER 给 posts 加 tags 列）；`GET /posts` 支持 `tag=` 过滤（LIKE 即可）；FE `square.js` state 加 `tag`（同 category 模式进 URL query，cat-bar 上方渲染 tag 面包屑）；`ui.js pinCard` 标题下渲染可点 tag chip → `#/square?tag=xxx`；`publish.js` 输入 # 时弹出候选话题；`seed.js` 给 24 帖补话题。
- **价值**：分类之外的二级聚合入口，承接 #周末去哪儿 / #i人友好 / #五道口 等长尾词，是搜索分词与话题运营的地基。**成本**：M（动 schema+seed+测试）；tag 渲染须符合 G 章"纯文本胶囊"规范。

### 3. 发布页场景模板（成本 S，约 0.5 天）
- **实现**：`publish.js` 选完分类后在标题框上方渲染 2-3 个模板 chip（本地常量按 category 映射：剧本杀/饭搭/运动/观影各一套 title+content+requirements 骨架），点击填入表单可改。纯 FE。
- **价值**：首帖完成率显著提升（模板预填地点/时间/要求结构）；模板化文案同时提高搜索命中与 H 章分类偏好的信号质量。**成本**：S。

### 4. 搜索历史 + 热门搜索（成本 S，约 1 天）
- **实现**：`square.js` `#f-kw` focus 时弹 `UI.sheet`：最近搜索（localStorage `dada_kw_history`，change 时写入、≤10 条、可清空）+ 热门搜索（先静态运营词"五道口 火锅""周末 徒步"，后期 `misc.js` 加 `/search-hot` 按查询聚合计 TOP）；点 chip 直接触发 refreshList。
- **价值**：把"想找什么局"的心智从逛 feed 转到搜索框，搜索即服务的入口形态；热门词兼作运营位（城市/节日热点）。**成本**：S（聚合后置则前后端各半）。

### 5. 收藏信号 + 热度权重修正（成本 M，约 2 天）
- **实现**：BE 新表 `favorites(user_id, post_id)` + `POST /posts/:id/fav` + postView 返回 `fav_count/faved`；FE 详情底栏加 bookmark 图标（H5-04 线性风格）；`posts.js` hot 排序与 `misc.js /recommend` 热度公式改为 approved > fav > comment > like > view 的降权序列。
- **价值**：补齐"收藏>点赞"的中强度信号（收藏=想去但时间不合，是复访理由）；热度修正防标题党局霸榜。**成本**：M（含新测试用例）。

## 四、落地顺序

1→3→4 先行（纯前端为主，一周内可全上，互不阻塞）；2、5 排 v3.0（动 schema，与 roadmap 的 LBS/群聊一起规划）。话题 tag 是搜索分词与 H 章分类偏好的公共地基，优先级应高于收藏。
