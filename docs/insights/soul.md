# Soul 经验反哺搭搭

> 视角：Soul 资深开发（陌生人匹配/安全风控）。对照搭搭 v2.9 实现：`server/src/match.js`、`web/public/js/pages/conv.js`、`server/src/routes/posts.js`（申请无频控）、`server/src/util.js`（搭力值/敏感词）。

## 一、破冰机制：Soul"先给画像再给人"，搭搭"给了人没给话"

Soul 的核心不是匹配算法，而是**匹配即附话题**：灵魂测试产出人格标签 → 星球匹配天然带共同点 → 匹配成功页直接给引导话题。破冰成本在产品侧被提前消化。
搭搭现状：conv.js 空会话只有一句"打个招呼/聊聊具体安排"（conv.js:155），申请留言是空文本框。双方标签数据其实都在（users.tags、post.category），但没被用于生成话术——数据在、场景缺。
解法：**破冰话题卡 + 申请留言智能建议**（见建议 1）。不引入 AI 也够用：模板规则"双方 tags 交集 × 帖子分类"即可覆盖 80% 场景，Soul 早期也是规则模板。

## 二、安全深水区：搭搭是"事后惩罚"，Soul 是"事中识别"

| 风险维度 | Soul 做法 | 搭搭现状 | 差距 |
|---|---|---|---|
| 频率异常 | 申请/私信行为序列建模，频繁操作降权+验证 | 申请无任何频率上限（posts.js:271-294 仅查重不查频） | 大：黑产批量申请耗尽组局者审批精力 |
| 秒发联系方式 | 新会话前 N 条含手机号/VX → 拦截+标记 | 仅静态导流词库打码，无"会话时长×消息序号"维度 | 中：词库永远追不上变体（V➕、徽信） |
| 设备指纹 | 一机多号识别（封号重开即关联） | 无。封号后重新注册成本≈0 | 大：搭力值惩罚可被"换马甲"完全绕过 |
| "照骗"与租号灰产 | 头像人脸聚类、同一头像多账号识别 | 头像零审核（users.js 仅限 5MB） | 中：酒托/婚托租号是搭子赛道高发 |
| 未成年人冒用 | 行为+人脸年龄估计 | 仅"学生认证"标记，无年龄下限校验 | 中：法律责任维度，出事即致命 |

搭搭搭力值/敏感词/SOS/女性局属于**合规基线**（已超同类独立产品），但全是"举报→人工→惩罚"后置链路；Soul 的教训是：等用户举报时，伤害已发生。下一步应把识别前置到"行为发生时"（见建议 3）。

## 三、关系沉淀：Soul"瞬间"的启示——内容是关系链的载体

Soul 留人靠瞬间广场：弱关系先通过内容持续曝光，多次轻互动后才升级为强关系。搭搭是"搭局→私聊→搭完即止"的单点脉冲，互评结束后双方再无触点。
搭搭的独特资产是**"搭过"这个强信任信号**（比 Soul 的兴趣匹配硬得多——线下真实见过面），但当前只沉淀为履历展示，没有回流到匹配：match.js 六维（tags/mbti/city/category/credit/active）中没有"历史搭过"维度，老搭子与陌生人同权竞争。
解法：搭友列表（互评≥4星自动入列）+ 老搭子在发现/广场优先曝光（见建议 2）。注意 match.js 的 WEIGHTS 有 Σ=100 测试断言（MT-05-2），加"搭过"维度建议做成**总分后置加分项**而非新权重列，避免破坏确定性评分契约。

## 四、可落地功能建议（按优先级）

**1. 破冰话题卡 + 申请留言建议**（约 1 人日）
- 要点：conv.js 空会话渲染 2-3 张话题卡（双方 tags 交集 + 该会话关联 post 的 category 模板库，纯前端规则生成，点击填入输入框）；apply 页基于帖子 title/category 给 3 条一句话模板（如"也想去这条 Citywalk 路线，我周末都空"）。
- 价值：直击"首条消息不知道说啥"——搭搭私信门槛高（先同局），每一句开场都珍贵；预期申请通过率与首日消息率双升。
- 成本：低。话题模板库 30 条起步，无后端改动（话题卡数据 conv 接口已含 other.tags，补 post 归属字段即可）。

**2. 搭友列表与老搭子匹配加权**（约 1.5 人日）
- 要点：互评≥4 星双向写入 `partner` 关系表；用户主页新增"搭友"Tab（含"搭过 N 次"标记）；matchScore 输出后 `score + 10×min(次数,3)`（clamp 100），发现页作者带"老搭子×2"角标。
- 价值：把"搭完即止"变成复购关系链；老搭子推荐成功率远高于冷匹配，同时天然对抗微信黑洞（站内有人等你）。
- 成本：中低。一张新表 + matchScore 后置加分（不动 WEIGHTS，不破坏 MT-05-2 断言）+ 两个页面区块。

**3. 行为风控规则（24h 申请上限 + 秒发联系方式识别 + 简易设备指纹）**（约 2 人日）
- 要点：① 申请频控——24h 申请 ≥10 局返回 429 并通知管理员（posts.js 一条 COUNT SQL）；② 会话建立后前 3 条消息内命中联系方式正则（手机号/微信号变体）→ 拦截 + 搭力值 -20 + 计入风控计数；③ 注册时记录 `sha256(UA+IP)` 指纹，同指纹 ≥3 账号标记待审。
- 价值：把风控从"举报后处理"推进到"发生时拦截"；黑产/约炮号的成本结构被直接抬高，搭力值体系才有牙齿（否则换号即重置）。
- 成本：中。全部基于现有 SQLite 计数实现，无外部依赖；指纹是简化版（准确率有限，但先解决"封号重开零成本"）。

**4. 会话内消息级快捷举报**（约 0.5 人日）
- 要点：conv.js 气泡长按（移动端）/ hover（桌面）浮出"举报此条"，直达现有 `/users/:id/report`，detail 携带 conv_id + message_id + 内容快照；运营后台举报队列联动展示证据。
- 价值：当前举报藏在"···"菜单第 3 层且不带消息证据（conv.js:217-232），人工核实只能翻库；快捷举报让女性安全场景（骚扰话术）30 秒内完成取证。
- 成本：低。纯前端交互改造 + report 接口 detail 字段透传。

## 优先级结论

先做 1+4（小成本、直接提升核心转化与安全体感），再做 3（防住灰产后再放量），最后做 2（需要存量搭局数据积累，但长期留存价值最大）。
