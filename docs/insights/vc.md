# 搭搭 · 早期VC视角商业分析

> 视角：看过社交赛道的早期投资人。结论先说：这个团队犯过赛道里最贵的错（戚越近百万学费），
> 且把四个死因做了工程化应对——但投资与否取决于一组现在还测不出来的数据。

## 一、冷酷的商业判断：这赛道的死亡规律与搭搭的活法

**赛道死亡规律（三条铁律）：**
1. **陌生人社交没有独立终局**。Soul 招股书折戟的核心不是增长，是变现与合规双杀；探探卖身陌陌；
   更大量搭子产品死于同一个曲线：冷启动靠补贴拉来两拨供需，密度不够 → 匹配失败 → 发帖者心灰意冷 →
   供给崩塌（豆瓣小组是唯一活的原型，因为内容社区不依赖即时匹配密度）。
2. **匹配成功即流失**（微信黑洞）：产品做得越好，用户越快毕业去微信。
3. **人性 decay**：目的性用户污染池子，女性用户先走，社区性别比失衡后整体死亡。

**搭搭凭什么活——我的判词：**
- **架构上"反毕业"设计是对的**：搭后互评 + 搭力值把信用锁在站内（离开平台信用清零），
  这是全赛道第一个把"搭子履历"做成资产的方案，等于给微信黑洞加了摩擦力。能否挡住取决于一件事：
  下一场搭子还得回这找——即履历有复用价值。履历冷启动（前3次搭局）体验决定生死。
- **单城密度 > 全国铺开**。14类场景 × N城市 = 无数个空城。活法是：一座城打透1-2个高频类目
  （饭搭/运动搭），密度起来再扩。SQLite 单机零成本恰好支持"一城一实例"打法，这是架构红利。
- **H5零安装验证顺序对了**（293赞教训），先证需求再烧钱，这个团队不会死于一百万，会死于数据盲区（见§三）。
- **真话**：天花板有限。搭子是低频高价值事件产品，估值模型对标闲鱼/大众点评（交易撮合）而非
  探探/Soul（高频社交）。按"本地撮合网络"估值，不按"社交平台"估值。

## 二、变现路径：先会员验证付费意愿，佣金等密度，装扮最后

| 顺序 | 路径 | 逻辑 | 定价锚点 |
|---|---|---|---|
| ① 先走（3个月内） | **会员「搭搭Plus」** | 零边际成本、纯软件，最快测出 ARPPU；搭力值体系天然是付费特权载体 | 行业锚：探探/Soul 会员 ¥25-50/月。冷启动期锚 **¥18/月、¥98/年**（低于锚点30%，教育期价格） |
| ② 第二（单城密度后） | **本地生活佣金** | 饭搭局带餐饮团购、旅行搭带票务；天花板最高但要先有撮合密度，否则商家不接 | 美团到店抽佣 ~10%；搭搭按 **8-12%** 起步，用"带局者返佣3%"激励组局者变成地推 |
| ③ 最后（履历生态成型） | 表情/装扮/履历皮肤 | 社交货币付费的前提是货币值钱——搭力值得先有炫耀场景 | 一次性 ¥6-12 低客单，不做大 |

**会员特权威慑力排序（按付费意愿强度）**：每日申请次数 5→15 次 > 按性别/认证/搭力值筛选 >
新局上线优先推送（抢手局先到先得）> 搭子履历无限回看。免费线必须守住：成搭和互评永远免费，
付费只加速撮合效率、不卖信任本身——卖信任（如付费改评分）会瞬间引爆 decay。

## 三、北极星指标与数据体系

**北极星：周成搭用户数（WPU）**——本周内参与至少一个 status='done' 搭局的独立用户数。
理由：搭子是事件型产品，DAU/刷帖时长是虚荣指标（游客可浏览，views 天然虚高）；
WPU 同时绑定供给质量、匹配效率、微信黑洞抵抗力三个死亡变量。**护栏指标：女性用户 WPU 占比 ≥35%**（跌破即 decay 预警）、举报率。

**核心指标定义（全部可用现有 posts/joins/ratings/messages 表算出）：**

| 指标 | 公式（现有表） | 诊断 |
|---|---|---|
| 申请通过率 | `joins(status='approved') / joins(全部)` | <50% 说明供给错配或审批过严 |
| 局成行率 | `posts(done) / posts(非open)` | 核心健康度；注意 done 靠手动标记，有水分 |
| 互评率 | `ratings行数 / (done局数 × 参与人数)` | 互评是信用飞轮入口，<40% 飞轮空转 |
| **搭后复约率**（第二北极星） | 同一 user 对在 `ratings` 中出现于 ≥2 个不同 post_id 的对数 / 至少共同成搭一次的对数 | 直接度量"挡住微信黑洞"是否成立，也是 LTV 之锚 |
| 复聊率 | `conversations.last_msg_at > 该局done时间` 的会话占比 | 低复约时的先导信号 |
| 浏览→申请转化 | `Σpost.joins / Σpost.views_count`（逐帖已有计数） | <2% 说明推荐/内容质量问题 |
| 供给新鲜度 | 近7天新建 open 帖 / 全部 open 帖 | 低于30%用户打开即看到僵尸帖 |

**埋点点位（现在一行埋点都没有，这是最优先的技术债）：**
建 `events(kind, user_id, post_id, meta, ts)` 单表 + 每日快照表，SQLite 下成本≈0。点位：
1. `posts.js` 帖子详情 GET → `view`（现 views_count 无 viewer 身份与时间，无法归因）
2. `POST /joins` → `apply`；审批通过/拒绝 → `approve/reject`（漏斗第二三级）
3. 标记 done → `complete`；互评提交 → `rate`（含 stars）
4. `chat.js` 首条私信 → `first_msg`；done 后再发消息 → `reactivate_chat`（复约先导）
5. 拉黑/SOS/举报 → guardrail 事件（女性护栏指标数据源）

## 四、可落地功能建议（按 ROI 排序）

1. **成搭漏斗看板进运营后台**——`admin.js /stats` 目前全是存量 count（users/posts/messages），
   无任何比率。加 events 表后用一条 SQL 出六级漏斗：浏览→申请→通过→done→互评→复约。
   价值：后续一切运营/融资叙事的地基；成本：**低**（1-2天）。
2. **搭局自动过期 + 到期提醒**——schema 里 `expired` 状态存在但**代码从不设置**，僵尸 open 帖
   永远挂着，供给新鲜度失真。meet_time 过 48h 定时转 expired，并推组局者"标记完成"。
   价值：数据真实性 + 提醒即互评触发点；成本：**低**（一个定时任务）。
3. **搭后复约提醒**——done 后 72h 未互评推送评价提醒；互评高分的旧搭子发新局时定向推送
   "你的饭搭又组局了"。复用现有 `notify()` 与 notifications 表。价值：直接抬北极星与复约率；
   成本：**低**。
4. **流失预警与唤醒**——`last_active_at` 超 14 天且有 done 记录的高价值用户进唤醒队列
   （推送同城新局/限免会员体验）。价值：挽回的是已验证付费潜力的老用户；成本：**中低**。
5. **被拒后可重新申请**——`joins` 表 UNIQUE(post_id,user_id) 导致被拒者永远无法再申请同局，
   一次拒绝即永久流失一个申请人。改为软删除/允许二次申请。价值：修复漏斗隐性漏水点；成本：**低**。

## 五、最危险的一个数据盲区

**没有事件日志，`last_active_at` 是单值覆盖**——只能知道用户"最后活跃"是何时，无法回溯任何
留存队列、漏斗、行为路径。这意味着：微信黑洞的真实流失规模（done 之后多少人再没回来）现在
**永远测不出来**，而且每过一天就永久销毁一天的数据。产品的核心论点（互评+搭力值能挡住流失）
恰好只能靠这组数据证明。**结论：埋点不是功能迭代项，是本轮该做的第一件事。**
